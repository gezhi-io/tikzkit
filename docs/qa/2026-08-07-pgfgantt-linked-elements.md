# `pgfgantt` Linked Elements QA (2026-08-07)

## Scope

This pass covers the `\ganttlinkedbar` and `\ganttlinkedmilestone` family:
each element is lowered as its normal bar or milestone and automatically gains
a dependency from the preceding Gantt element. The visual driver is
`test/fixtures/examples/pgfgantt/linked-elements.tex`, adapted from the
installed `pgfgantt` manual. It creates Design, linked Build, linked Release,
and linked Follow-up with a red `link/.append style`.

This slice does not claim `\ganttlinkedgroup` shape parity, calendar/date
slots, progress, title lists, custom `\newganttlinktype` declarations, or
arbitrary anchor styles.

## Local MacTeX Study

Read locally:

- `/usr/local/texlive/2025/texmf-dist/tex/latex/pgfgantt/pgfgantt.sty`;
- `/usr/local/texlive/2025/texmf-dist/doc/latex/pgfgantt/pgfgantt-doc.pdf`.

The relevant source is direct rather than inferred:

- lines 849-993 retain `\gtt@lastelement` and `\gtt@currentelement` after
  every chart element, including automatic `elemN` names;
- lines 996-1025 define every `\ganttlinked...` macro as normal element
  creation followed by `\ganttlink{last}{current}`;
- lines 1129-1151 define milestone defaults as `draw, fill=black`, italic
  labels, `.6/.4` horizontal shifts, and `.3/.4` vertical shifts.

TikZKit now mirrors that sequence. It registers the current element bounds,
queues an implicit link when the input command was linked, and lowers the
queue through the existing source-anchored link logic. Milestone geometry is
calculated from the reviewed shifts: its center lies on the time slot, its
horizontal half-width is `.4 × x unit`, and its vertical half-height is
`.2 × y unit chart`.

## Three-Renderer Evidence

`tikztosvg` was available at `/Library/TeX/texbin/tikztosvg`; PNG conversion
used `/opt/homebrew/bin/rsvg-convert`.

Before the implementation, a detached baseline from commit `9ca8d9f` rendered
the same source into
`outputs/qa-pgfgantt-linked-elements-before-2026-08-07/`. Its TikZKit panel
contained only the title and the initial Design bar. Build, Release, Follow-up,
and all three red dependency links were absent, while MacTeX and tikztosvg
contained the complete chart.

After implementation, all artifact types are in
`outputs/qa-pgfgantt-linked-elements-after-2026-08-07/`:

- MacTeX PNG: `mactex-png/pgfgantt-linked-elements.png`;
- TikZKit SVG/PNG: `tikzkit-svg/pgfgantt-linked-elements.svg` and
  `tikzkit-png/pgfgantt-linked-elements.png`;
- tikztosvg SVG/PNG: `tikztosvg-svg/pgfgantt-linked-elements.svg` and
  `tikztosvg-png/pgfgantt-linked-elements.png`;
- comparison sheets: `diff/pgfgantt-linked-elements-native-sheet.png` and
  `diff/pgfgantt-linked-elements-sheet.png`.

The inspected TikZKit after panel visibly restores all three bars/milestone
dependencies: Design to Build routes right/down/right, Build to the black
Release diamond follows the same automatic route, and Release to Follow-up
uses the native automatically selected RDLDR detour. The diamond is now black,
slot-centered, and its `Release` label is italic at the same chart row as the
native references. Small remaining differences are SVG canvas size and glyph
rasterization, not missing tasks, dependencies, arrows, or milestone semantics.

The tikztosvg SVG confirms the geometry: its three red dependency stems are
separate paths with `stroke-width="1.19553"`, round-corner cubic transitions,
and separate filled red Latex-tip paths. Its milestone is a separate black
four-point diamond path. TikZKit emits the same semantic decomposition: normal
paths with inline Latex tips generated by the SVG renderer and a black filled
diamond in the shared scene graph.

## Changes And Verification

- `src/frontend/latex-shell.js` parses linked-element command names, reuses
  bar/milestone lowering, retains preceding element identity, and queues an
  implicit `\ganttlink`; it also corrects source-reviewed milestone default
  fill, label, position, and dimensions.
- `test/walmes-compat.test.js` verifies the two predecessor links, their red
  Latex tips, the black default milestone, and linked labels.
- `test/fixtures/examples/pgfgantt/linked-elements.tex` and its manifest entry
  provide the real browser/reference example.
- `src/packages/pgfgantt.js`, the generated extension registry, and README
  record the supported and remaining boundaries.

```bash
node --test --test-name-pattern='pgfgantt' test/walmes-compat.test.js
npm run examples:render -- --fixtures test/fixtures/examples \
  --output outputs/qa-pgfgantt-linked-elements-after-2026-08-07 \

npm run examples:diff -- --output outputs/qa-pgfgantt-linked-elements-after-2026-08-07 \
  --register --alignment-radius 3

```

The focused regression passes. MacTeX, tikztosvg, and TikZKit each generated
the driver with no TikZKit diagnostics, and the after panel has a clear visual
improvement over the pre-change baseline.
